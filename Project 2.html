Project 2: Machine Learning and Home Loan Data¶

Problem and Dataset¶

Given the current economic environment and the focus on interest rates and housing, I'm curious about what elements inform whether someone is approved for a mortgage loan.

In particular, I'm curious what elements inform whether an applicant, who is a typical American homeowner, is approved for a refinancing loan. One's home is the primary investment vehicle for many in the US, and in tumultuous economic times it can be a valuable line of credit. It can be invaluable for local, state, and federal governments, along with financial institutions, to accurately predict which members of the population are likely to have access to this lifeline, discrepancies in who may have that access, and who in the population may be more economically at risk.

The data set I am using is mortgage application data provided by the Consumer Financial Protection Bureau (CFPB), specifically for North Carolina in 2017.

Using data specifically for North Carolina helps control for different housing markets and lending laws across states. North Carolina's demographic diversity also helps for testing demographic bias in loan approval, along with my own personal interest in my home state.

As 2017 was a fairly stable year economically compared to today, I believe it can serve as a test case for a healthy market. This data can then be used to gauge current market conditions or shifts in what elements lead to loan approval. Refinancing tends to have a lower approval rate and can give insights into the economic health of homeowners along with the lending environment.

The target is loan approval, and machine learning executing via Sciit learn python library to compare two classification models, a linear regression and random forest model. The data will be controlled for a refinancing loan being approved for a first lien, owner occupied, 1-4 family dwelling. This mitigates issues with loans for different types of boworers and properties being subject to different laws.

While this project will focus on loan approval and comparing the effectiveness of different models, a part 2 of this project will be modeling the loan amount for approved loans, and in the code there will be some reference and setup to this end.

Dataset source: CFPB Home Mortgage Disclosure Act data (HMDA)

  • Field values: “Geographic area” = North Carolina, “Records included” = “All Records”, and “Variable descriptions” = “Plain language labels and HMDA codes”, year is 2017
    • Plain datasets with only HMDA codes unavailable at time of writing.

Variables and Dataset Characteristics¶

  • Total number of rows: 464,109 (uncleaned/refined), 93,881 (cleaned/refined)
  • Total number of columns: 78 (uncleaned/refined)
    • The dataset contains duplicates of features: One that is encoded with String name data (features with _name appended at the end), and a copy that is numerically encoded with standardized HMDA codes.

Target¶

  • Loan approval and loan amount (in thousands USD)
  • action_taken convert to binary 0/1 target, loan_amount_000s log-transformed
    • Log-tranform helps reduce outlier distortion

9. Train/test split¶

The data is split 80% training / 20% test, stratified on the target so both sets keep the same 73% approval rate. The test set is set aside and used only once, for the final evaluation. All model tuning uses cross-validation within the training set, so the test set never influences any modeling decision.

The fairness columns are split along with the features (same rows), so the audit in Section 15 can be run on the test set.

10. Preprocessing pipeline¶

Preprocessing is wrapped in a ColumnTransformer inside each model's Pipeline, so every step that learns from data (the median used to fill missing income, the mean and standard deviation used for scaling) is fit only on the training portion of each cross-validation fold. This prevents information from the validation or test data from leaking into training.

Feature type Steps
Numeric Fill missing values with the training median -> standardize (mean 0, SD 1)
Binary (0/1) Passed through unchanged
Categorical One-hot encode (categories unseen in training are ignored)

Strategy to use to generate predictions.

* "most_frequent": the `predict` method always returns the most

  class distribution of `y` also known as the empirical class prior
  distribution.

12. Model training and hyperparameter tuning¶
Two models are compared:


    

  • Logistic regression: a linear, highly interpretable model. Its coefficients show the direction and strength of each feature's association with approval.
    • 

  • Random forest: an ensemble of decision trees that can capture nonlinear relationships and interactions (for example, income mattering more for some loan types).
    • 



Both use class_weight="balanced", which gives denials more weight during training so the models don't simply learn to predict "approved" for everyone.


Hyperparameters are tuned with grid search and cross-validation on the training set, using ROC-AUC as the selection metric because it measures how well a model ranks approvals above denials regardless of the decision threshold.

12.1 Logistic Regression Analysis¶

A small C (<1) equates to strong regularization and heavily penalizes misclassification, but risks underfitting. Using the 1-10 rule, where it is recommended that there be 10 outcomes in the minority class (events) per variable, having 19 columns for ~20k denials leaves the ratio at nearly 100 times the guidline. This helps explain why C tuning did little as there wasn't much of a risk of overfitting.
